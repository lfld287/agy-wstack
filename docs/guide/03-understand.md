# 动手前先理解代码

不理解代码就修改，容易把隐蔽的回归带上线。代理和人都一样。代理常见的两类失误是误读你的意图，或缺少把工作做对的上下文。第一类见[提示词写哪些内容](./02-poteto-mode.md#what-goes-in-a-prompt)，这里处理第二类。

pstack 提供四个入口。`/how` 解释代码现在做什么。`/why` 追查代码为什么是现在的样子。`/teach` 把两者合成一份讲解。`/recall` 重建你在某主题上的近期上下文。这些技能都要求代理用你能核查的话解释自己的结论。即使代理比你熟悉代码，你也能据此监督它。

![侦探用放大镜查看机器蓝图，机器人在找案卷。她身后的证据板把线索连到 /how 和 /why 下。](./images/understanding.jpg)

## 先做只读调查

成因不清楚时，先要调查结果。

```text
/poteto-mode 调查后台任务为什么每隔几小时就超时。告诉我已知事实、用到的数据和最可能的假设。先别改代码。
```

「先别改代码」会将任务路由到 [Investigation playbook](../../skills/poteto-mode/playbooks/investigation.md)。它追踪代码，有关设计动机的问题加用 `/why`，最后提交有出处的说明。需要在多个方案中选择时，它会给建议，并附取舍表。问「用到哪些数据」能让代理把证据与猜测写清楚。如果调查结果指向一个修复，把修复作为新任务启动。

## 用 `/how` 追踪行为

```text
/how 我们怎么做通知去重？查订阅者时有没有 N+1 查询？
```

直接问你实际关心的事。[`/how`](../../skills/how/SKILL.md) 读代码，以资深工程师带你熟悉子系统的深度说明运行流程、关键类型和不明显的细节。它用 `invoke_subagent` 启动一个只读调查代理，由该代理探索代码并写说明。

## 用 `/why` 查历史

```text
/why 重试上限为什么设为 5？当初的理由现在还成立吗？
```

[`/why`](../../skills/why/SKILL.md) 从历史记录找答案。它读取引入代码的提交和 PR 讨论，以及后续每次修改的记录。线索不够时再找其他来源。回答引用作者原话，标明哪些判断是代理自己的推断，并交代记录没有回答的问题。「没人写下过原因」本身也是答案。

两个技能可以组合使用。怀疑历史能解释现状时，可以说「先用 why，再用 how」。

## 用 `/teach` 听懂改动

```text
/teach 讲讲这份 PR 怎么改了重试。说服我，它修到了根因。
```

摘要还不够时，用 [`/teach`](../../skills/teach/SKILL.md)。它运行 `/how` 和 `/why`，小改动可能只用其中一个，再把发现写成一份平实的讲解，配合逐步展开的图。「说服我」这种说法值得复用。它会让说明成为可以核验的论证。

也可以问代理自己的选择。

```text
/teach 解释为什么你用了现在的实现。和队列方案相比做了哪些取舍，原因是什么？
```

讲解也帮助代理检查自己的判断。代理要解释工作，就得读代码并为每个主张提供证据，不能仅凭语气肯定地略过。

## 用 `/recall` 复原工作上下文

```text
/recall 帮我回顾上周的导出工作。
```

[`/recall`](../../skills/recall/SKILL.md) 调查你近期的聊天和共享记录（工单、以往修复、仍在触发的错误），给出一份关于现状和下一步的简报。旧聊天里有新代理缺失的上下文，所以回到旧主题时先加载它，再递交新的材料。

```text
/recall 回顾我昨天在虚拟列表上的工作，然后读这份缺陷报告。
```

接续某次特定聊天时，使用下面的 Session pickup playbook。

## 用 Session pickup 接手旧工作

另一个代理或上周的你把一个分支做到一半时，可以这样说。

```text
/poteto-mode take over this branch. 读决策日志，弄清已完成的工作，接着往下做。跳过已完成的步骤。
```

[Session pickup playbook](../../skills/poteto-mode/playbooks/session-pickup.md) 把已有的工作记录作为依据。它重建分支状态与此前的决定，指出续接位置，再按原目标核验接手来的主张，省去从头推导。

**常见陷阱。** 别因为「代理反正会读代码」就跳过这里的技能。没有追踪出运行机制就动手，容易在第一个看似合理的位置修补症状。先用 `/how` 比处理第二个缺陷便宜。
