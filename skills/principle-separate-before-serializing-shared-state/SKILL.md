# 先隔离状态，再考虑串行化写入

并发参与方可能写入同一个文件、分支、键或对象时，先判断它们是否确实需要同一个共享对象，还是仅在发布各自独立的信息。默认给每个参与方独立的文件、键、分支或状态目录，只在读取状态时合并。两个执行者各自写入同一个 `state.json` 中不同的字段，仍然是在修改共享状态。

只有各方必须写入同一个目标这一约束确实成立时，才使用锁文件、单一写入者、顺序执行的阶段或比较并交换（CAS）等机制将访问串行化。单靠文字指令无法控制并发。有人说「我们需要一把锁」时，先重新检查是否必须共享写入目标。
