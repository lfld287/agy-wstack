# Bugbot 评论分流

在 `babysit` playbook 处理 Bugbot 或其他自动审查评论时使用。AGY 通过当前 forge 读取 PR 检查和审查线程，例如在 GitHub 上用 `gh pr view` 查看检查，用 forge 的审查线程工具读取评论。没有 Bugbot 检查或评论时，跳过启动、配置和等待 Bugbot 的步骤，继续处理其他检查与人工审查。先判定每个线程是否需要代码修改。

## 决策标准

| 分类 | 条件和处理 |
| --- | --- |
| `fix` | 评论指出有证据支持的正确性、安全、隐私、数据丢失、鉴权、计费、迁移、幂等、竞态或已交付行为问题。在最靠栈底且拥有该改动的 PR 修复。核验后，按授权用提交 SHA 回复并解决线程。 |
| `dismiss` | 符合已记录的低风险误报模式，且当前代码和上下文证明无需修改。按授权简短回复理由并解决线程。 |
| `ask` | 新型问题、高严重度问题、安全／隐私／数据问题或有歧义的发现，现有证据不足以直接定夺时，请操作员判断。 |

判断不清时选 `ask`。避免将可能影响数据或安全的问题按风格噪声处理。后台 worker 将需裁决的项交给主会话，主会话用 `ask_question`，并继续能处理的其他线程。外部回复和解决线程需要操作员授权。

## 模式记录格式

```markdown
### <模式名称>

- 置信度：candidate | recurring | strong
- 可忽略条件：<必须同时成立的条件>
- 保留条件：<风险边界>
- 识别线索：<典型措辞或代码上下文>
- 来源：<PR、评论 URL 或历史说明>
```

一两例用 `candidate`。有多次实际驳回记录后用 `recurring`。只有匹配范围窄、反复核实、风险低的模式用 `strong`。

## 反复出现的候选模式

### 有意修改 UI 或设计系统视觉样式

- 置信度：`candidate`。
- 可忽略条件：PR 说明、截图、设计审阅或附近代码证明视觉默认值是故意变更，评论只重述该变化。
- 保留条件：涉及无障碍、焦点可见性、键盘导航、对比度或未明确改变的组件 API 契约。
- 识别线索：焦点轮廓、按钮尺寸、间距或共享组件默认样式，负责人已确认是有意变更。

### 当前 PR 看不到栈上用法

- 置信度：`candidate`。
- 可忽略条件：机器人说导出、组件、辅助函数或文件未使用，后续 PR 的 diff 或上下文证实存在用法。
- 保留条件：当前 PR 不在栈中、符号属于公开 API，或无法核实栈上用法。
- 识别线索：「导出的组件未使用」，人工回复「上层 PR 使用」。

### 并行实现期间的暂时重复

- 置信度：`candidate`。
- 可忽略条件：为了并行验证，新旧路径短暂共存，仅复制少量代码，旧路径有明确替换或删除步骤。
- 保留条件：重复逻辑影响安全、计费、数据访问、API 行为，或长期共享抽象明显能降低风险。
- 识别线索：「显著重复」或「重复的校验逻辑」，上下文表明是同一小范围的临时重复。

### 现有框架或组件不变量覆盖告警

- 置信度：`candidate`。
- 可忽略条件：当前 diff 或附近代码中的共享组件、类型不变量或单一事实来源已保证该约束。
- 保留条件：不变量只是推测、依赖时序，或跨异步／状态边界造成值可能分离。
- 识别线索：组件已强制最大高度，类型已保证非空，或读写使用同一值。

### 负责人明确安排后续清理

- 置信度：`candidate`。
- 可忽略条件：PR 负责人明确记录为后续事项，当前行为未变差，且事项属于低风险范围。
- 保留条件：负责人未参与判断、产品行为风险达到中度或更高、合并会引入回归。
- 识别线索：「后续处理」或「最终会删除」。

### 机器人撤回或明确标为误报

- 置信度：`recurring`。
- 可忽略条件：评论正文或机器人后续回复明确撤回，或确认当前实现合规，且可在本机核实相关规则。
- 保留条件：高风险发现只有人的一句「误报」，没有说明和证据。
- 识别线索：文件命名评论明确说当前文件已符合规则。

## 默认提交操作员判断

- 安全、隐私、鉴权、计费、数据保留、训练数据和权限边界。
- 高严重度问题。
- 迁移、schema、幂等、并发及跨系统行为。
- 建议改动小、明确降低风险且保持产品意图的评论，应优先验证并修复，证据仍不充分时交由操作员判断。

以往负责人驳回过安全或数据流评论。把这些决定保留在其具体上下文内。

## 近期任务的候选经验

在追踪 PR 期间或之后补充可复用经验。多次证实后再升级置信度。

### 手工重写原生浏览器行为

- 置信度：`candidate`。
- 可忽略条件：极少适用。曾有改动用 JS 定位副本替代原生 sticky，用转发滚轮和触摸事件替代原生滚动目标，或用遮罩和裁剪替代基于绘制顺序的遮挡。相关逻辑问题应逐项验证。
- 保留条件：事件转发遗漏（`deltaMode`、触摸平移、边缘滚动链）、遮罩或裁剪与命中检测分离、观察器与 UI 状态更新之间的时序问题。
- 识别线索：「遮罩不影响命中检测」「覆盖层挡住滚轮滚动」「忽略 `deltaMode`」「在状态刷新前执行 IntersectionObserver 回调」。
- 来源：一次 sticky 遮挡 PR 经六轮 Bugbot 审查，约十八项发现均修复。

### 契约测试和文字可能漂移时先跑测试

- 置信度：`candidate`。
- 可忽略条件：PR 用正则或快照把测试与文档、协议文字绑定时，在当前 PR 头运行该测试。相关断言通过即可作为针对这条评论的证据。
- 保留条件：相关断言失败时修复并复验。多轮修复改过文字时仍需重新运行。
- 识别线索：「契约测试漏掉修复前的等待」。
- 来源：一次 PR 的第七轮审查指出文本漂移，当前头上的测试恰好在该断言失败。

### 同一 PR 的后续提交已补齐安全校验

- 置信度：`candidate`。
- 可忽略条件：当前 PR 头已有评论所指的授权或校验，并用对应测试证明该路径强制执行。
- 保留条件：检查只是空操作，调用晚于受保护副作用，或测试未覆盖评论所指调用者。
- 识别线索：「高危，缺少授权检查」，后续加固提交包含对应检查。

### 扩宽精确的错误条件会掩盖真实失败

- 置信度：`candidate`。
- 可忽略条件：窄分支保留有意义的区别。例如只在 `ENOENT`（命令未安装）时用后备命令。将所有非零退出都当作缺少命令会掩盖认证、网络或执行失败。
- 保留条件：条件漏掉同类错误，例如同属二进制不可用的 `EACCES`，或未处理路径遗失数据、留下部分状态。重试幂等且原错误仍能看到时，验证可否补齐缺失分支。
- 识别线索：「仅 `ENOENT` 时从 X 回退至 Y，有效命令返回失败时仍不回退」。
- 来源：一次 CLI 重命名 PR，后备路径针对缺失二进制。
