### 重构

**由你守住行为契约。只改结构，保持现有行为。** 增加行为走[功能开发](feature.md)，纠正行为走[缺陷修复](bug-fix.md)。

若清理时发现功能缺失或真实缺陷，另行处理，先按已固定的契约交付结构改动。可以重新设计，但要点明并转[功能开发](feature.md)。大型或横切的结构改动用 **figure-it-out**。本手册适用于局部到中等规模的改动。

1. 先固定行为契约。跟踪受影响的子系统厘清契约，在移动结构前用现状刻画测试、快照或等价性验证工具记录当前行为。没有覆盖时先补上行为基线，再动结构。类型检查和 lint 无法固定原有行为。
2. 按 **principle-model-the-domain** 指明代码缺少哪种结构。简单、清晰且局部的代码保留。调整结构应删掉分支或无效状态，避免新增间接层。
3. 说明目标结构。按 **principle-foundational-thinking** 和 **principle-redesign-from-first-principles**，写明今天从头做会采用的模块布局、类型和调用图。跨函数边界时，先用 **architect** 定好结构再动手。
4. 先减后加。引入新结构前，删死代码，去掉只有一处调用的封装、冗余校验和孤立引用（**principle-subtract-before-you-add**）。按 **principle-laziness-protocol**，只交付达到目标结构所需的最小改动。撤回「也许有用」的试探性清理。
5. 分小步移动代码，每步保持行为基线通过。调整 API 时，同一轮迁移全部调用方并删除旧 API（**principle-migrate-callers-then-delete-legacy-apis**）。禁止保留兼容垫片或新旧并行路径。对着实际文件逐个抽查改名，字符串、文档和反向引用很容易漏。按模型配置的 `feature, refactoring` 角色委派机械改动，原生 AGY 默认 `Model: "pro"`，也可用配置的外部模型。按[自主执行](autonomous-run.md)的 AGY 调度约定选择推理强度，并交代文件路径、迁移的名称和应维持的行为。
6. 按 **principle-prove-it-works** 在真实产物上证明行为一致，编译通过只是前提。较大的结构调整要做等价性检查，可以用脚本对比新旧输出，拿录制的基线在新代码上重放，或用对应控制手段在匹配的使用界面跑冒烟验证。
7. 确认值得保留。以降低阅读负担为成功条件（**principle-minimize-reader-load**）。若改动没有降低任何一处的阅读负担，就撤回。
8. 用 rebase 整理成小而有序的提交，先删减，再调整结构，最后做后续清理。按 **principle-sequence-verifiable-units** 组织提交，每个保行为的单元通过后再继续。执行[开 PR](opening-a-pr.md)。

**回复**应包含改了什么结构、用哪份契约固定行为、等价性证据、阅读负担如何变化、交付及撤回了什么。不得引入新行为。
