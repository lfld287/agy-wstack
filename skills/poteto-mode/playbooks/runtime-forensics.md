### 运行时取证

**由你负责诊断。给运行中的进程插桩，用现场证据作判断。** 交付附有出处的诊断。

1. 用匹配的控制手段采集现场信号。进程空转就采 CPU profile，内存泄漏就抓 heap snapshot，视觉异常就抓 CDP trace。留存实际产物。
2. 把产物收敛到关键证据，例如热路径上的函数、从泄漏对象到 GC root 的保留链、没有输入却反复触发的循环。按 **principle-guard-the-context-window**，把大文件解析交给子代理，主会话只留提炼结果。按[自主执行](autonomous-run.md)的 AGY 调度约定选模型和推理强度。
3. 先证实机制。可通过 CDP eval 向运行中的进程注入探针，或在不重载的情况下对运行中的代码做临时热修，低成本验证假设。
4. 把结果映射回源码，列出文件、符号和执行分配或调度的行。
5. 并行检查点只写一行 `throughput checkpoint: n/a, read-only forensics`，表示只读取证，无需拆分实现。

**回复**应包含采集的信号、提炼的结论、机制的证明方式、源码位置和产物路径。用户未要求时只交诊断。根因查明后，可转[缺陷修复](bug-fix.md)或[性能问题](perf-issue.md)。
