### 评测

**由你负责实验设计、盲法、执行和结果归纳。**

**盲评的硬性要求**

- 候选执行者可见的目录、文件或提示中不得出现 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate`、`arena`，以及 `候选方案/`、`评分标准.md`、`评测`、`盲评` 等会暴露评测背景的中文标记。
- 提示要像用户自然提出的请求，只交代要达成的目标，隐藏评测背景。
- 避免暗示应走哪条技能链。别要求列出用到的技能、原则或文件。可以笼统地要设计说明，技能链是否遵循由代码结构和实际记录判定。
- 清理目录名和短标识，使用用户在真实项目中可能取的名字。
- 不告知候选执行者还有其他人做同一任务。
- 评审者可以知道自己在评分，但产出只用脱敏标签标识，隐藏模型名。
- 对比两个变体时，由同一评审者在同一轮按同一尺度评两组，隐藏每组来自哪个变体。

**步骤**

1. **界定实验。** 写清待测变体和成功行为。拟定 3–6 条具体评分标准，仅供评审者使用。
2. **准备脱敏环境。** 每个候选执行者有独立工作目录，放入对应变体。布置真实任务自然会有的上下文，例如项目骨架和执行者本来就会读的技能。
3. **写一份自然的提示。** 按真实用户的方式表述，隐藏测量内容。
4. **并行派出 N 名候选执行者。** 按 [`arena` 的 A 阶段第 3 步](../../arena/SKILL.md#a-定题)选不同模型，按 [B 阶段](../../arena/SKILL.md#b-并发生成)派工。每人在独立脱敏目录工作，收到同一份提示。按[自主执行](autonomous-run.md)的调度约定混用 `agy:*` 与 `codex`、`pi` 后台任务。外部任务启动前选能保留工具调用轨迹的方式，供第 6 步核对。通用分发脚本默认用临时会话，仅凭最终输出无法核验文件访问时，改用能留存相关轨迹的 CLI 启动方式。按角色和工作难度选模型与推理强度。仅负责派发、轮询或打包结果的角色用中等推理档，原生 AGY 可用 `Model: "flash"`。
5. **派出一名盲评者。** 按 [`arena` 的 C 阶段](../../arena/SKILL.md#c-交叉评审)选择只读评审，核实其实际模型家族与候选执行者不同。只交评分标准和脱敏标识的产出，不交模型名。
6. **用会话日志核对实际执行链。** 仅查看本工作区本轮候选会话对应的 AGY 日志。优先使用宿主提供的 `transcriptPath`，不可用时按会话 ID 回退到 AGY CLI 默认路径 `~/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`。外部 CLI 使用派发时记录的该任务会话或工具调用日志。禁止在所有项目目录里做通配扫描，以免跨越工作区边界读取无关的私密会话。核对实际打开过的文件，结合代码结构判定是否遵循技能链。缺少可核查的轨迹时标为未验证，候选执行者的自述不能补足证据。
7. **亲自从头读完全部候选产出。** 对照评审结论。有分歧时检查模型偏差或评分标准歧义，再给出综合结论。

**回复**应包含待测变体、评分标准、逐项候选记录、盲评结论、综合判断，以及是否采用该变体的建议。
