### 多阶段或多 PR 计划

**由你负责计划。负责人逐项执行，操作者逐项看证据。** 计划本身就是交付物，写完不进入实现。

1. 改动只有一两个文件且做法明确时，跳过计划，指出原因后停止。
2. 动笔前按[原型](prototype.md)试验并解决未定问题。只有实验无法决定的产品或偏好问题，才用 AGY `ask_question` 请操作者决定。
3. 写计划文件。开头说明改什么、各 PR 编号及落地顺序，以及依赖图。图中说明哪些 PR 独立并从主干分支、谁等待谁、各自可改哪些文件。随后每个 PR 一节。按 **principle-sequence-verifiable-units**，一个 PR 只做一项改动，并提供独立证据。每节用复选框列依赖、修改文件、该项改动、可观察结果和验证。
4. 单靠测试不能算验证完毕。单测、实际运行和性能三类复选框都打勾，PR 才算验证过。每个实际运行项都要在真实使用界面执行具体场景，并写明通过条件。性能项须写指标、测量方法、预先实测的主干基线和判定失败的数值。涉及交互变化的 PR，合并前须等操作者评审。
5. 交回计划路径后停止。操作者明确同意才开始执行。

**回复**应包含计划路径、各 PR 编号与依赖、需要操作者评审的 PR，以及尚未证明的事项。
