### 接续会话

**由你确定接手点。先读既有记录，再从中断处继续。**

1. 找到上一轮的记录。可用当前工作区的 AGY 会话日志、子代理会话链接、外部后台任务记录或已推送的分支。读取 AGY 日志时，优先使用宿主提供的 `transcriptPath`，不可用时按会话 ID 回退到 AGY CLI 默认路径 `~/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`。只按已知会话 ID 或任务记录读取本工作区日志，禁止在所有项目目录里通配扫描，以免读取无关项目的私密会话。先看元数据摘要和末尾消息，再向前找决策点。按 **principle-guard-the-context-window**，长日志交给子代理解析，主会话只保留提炼后的时间线。按[自主执行](autonomous-run.md)的 AGY 调度约定选择推理强度。
2. 还原执行状态，包括分支、工作树、已落地的改动（`git log`、相对基线的 `git diff`）、未办事项和已有决策。以既有轨迹作为权威输入，避免重新推导一遍。
3. 对比已做和未做。拿已交付内容对照计划，点明恢复点。不要重跑上一轮的复现过程或重做已完成事项。「从头验证一遍」会丢掉已有的可信工作轨迹。
4. 将剩余工作交给匹配的手册并决定接续方式。可以继续执行、交付完整建议、确认或推翻原结论，也可以为失败的运行做复盘。接续手册到此结束，余下步骤由选中的手册负责。
5. 按 **principle-prove-it-works**，用真实产物对照原始目标核实接手的主张。前一位代理自述通过不能当作证明。

**回复**应包含上一位代理停在哪里、你接手和重做了什么（尽量无重做）、恢复点和结果。
