# 构建撬动工作的工具

工作只要超过举手之劳，就构建能执行或验证它的工具，例如代码转换工具（codemod）、脚本、生成器或可重复运行的检查。是否需要工具取决于工作有多简单。即使只做一次，也适用这条原则。只有寥寥几处一目了然的改动才可以直接手改。

- 手工完成第一个单元，再构建工具，并在同一单元上重新运行它来验证效果。确保工具可以安全重跑。
- 优先使用确定性工具。确实需要通过 `invoke_subagent` 分派工作时，把操作步骤、验证约定和操作边界写进同一份技能，让受委派者可以读取，但无法修改。
- 应用这条原则会产出一个文件。如果差异中没有脚本、代码转换工具、生成器或供子代理使用的技能，就说明还没应用这条原则。如果这项工作会延续到本次会话之后，将工具提交到版本库。
- 写一个足以执行或验证任务的最小脚本即可，无需搭建框架。
