# 体验优先

当实现上的便利与用户体验冲突时，优先照顾用户体验。

- 每项功能、每个控件、每个选项都应有保留的理由。
- 少做但做好。三个打磨完善的功能，比十个粗糙的功能更能带来好体验。
- 定案前先做原型。在用完即可丢弃的 HTML 原型上做设计决策，比在生产代码里做成本更低。
- 把细节做到位，包括过渡、对齐、间距、反馈和错误状态。
- 把核心操作流程理顺。每项功能都应服务于核心流程，否则就别挡路。

凡是使用工作成果的人，都是用户。UI 的用户是终端用户，库或内部 API 的用户是导入它的同事，接手维护代码的工程师也是用户。同样重视他们的体验，并从他们的角度说明影响。

基础应服务于体验。基础先行决定工作*先做什么*，体验优先决定工作*要达到什么目标*。
