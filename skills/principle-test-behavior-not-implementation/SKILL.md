# 测试可观察行为

测试描述代码使用者能通过接口观察到的结果，包括返回值、错误、可读回的状态，以及对外部系统产生的影响。私有辅助函数、内部调用顺序和中间数据属于实现细节。

设想以下两种改动，用它们检验每个测试。

- **破坏行为。** 例如返回错误的值，漏掉某个外部影响，或使某个影响重复发生。如果测试仍通过，就没有证明任何东西。常见原因包括断言过于宽松、预期值由被测代码计算，或断言的对象是测试自己构造的数据。
- **改变内部实现。** 保持所有可观察结果。如果测试失败，就说明它绑定了实现细节。

保留能捕捉第一种改动、又能经受第二种改动的测试。其余测试重写或删除。用具体输入通过公开接口运行代码，并从需求推导预期值。外部服务收到的内容属于可观察行为，内部辅助函数的调用属于实现细节。断言「这永远不会发生」时，也要配一个它确实会发生的用例。断言调用方用来判断分支的错误类型，避免把错误消息写成测试契约。
