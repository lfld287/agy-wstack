# 纠正反复发生的错误

操作人在这个仓库里反复纠正代理犯的同一类错误。修改仓库，让下一个代理无法重犯。

假设每位贡献者都是代理，只看过自己打开的文件，会就近照抄例子，并选最短的、能编译通过的路径。把仓库设计成从一个文件看起来合理的改动，放到整个仓库也成立。

## 找出错误类别

先读近期提交、回退记录、评审评论、代理指令文件，以及解释权宜做法的代码注释。把错误归类，同类错误出现两次才计入。

也查阅已确认属于当前仓库的 AGY 会话，收集操作人纠正代理的原话及相关行为。按当前会话 ID 或可信元数据已确认属于本仓库的历史会话 ID，定位 `~/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`。用 `read_file` 定点查看，或用 `run_command` 逐行解析 JSONL。下例仅使用已确认的 ID。

```sh
log_dir="$HOME/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs"
jq -c 'select(.type == "USER_INPUT" and .source == "USER_EXPLICIT") | {step_index,created_at,content,truncated_fields}' "$log_dir/transcript.jsonl"
```

结合相邻代理回复和工具结果确认实际错误。摘要条目缺失或被截断时，按 `step_index` 查同目录的 `transcript_full.jsonl`。证据记会话 ID 和步骤索引，禁止跨工作区扫描日志。

## 在能奏效的最高层解决每类错误

1. **用架构消除。** 每份状态只有一个所有者，每项任务只有一条受支持的路径。隐藏内部实现，让错误的导入立即失败。把需要手动同步的列表换成唯一事实来源。删除代理可能照抄的过时路径和死代码。
2. **用类型阻止非法状态。** 错误代码仍能编译时，就加 lint 或 CI 检查，在报错中指出应该改用的文件、类型或函数。如果错误模式已大量存在，仅在改动新增实例时让检查失败。
3. **测试行为。** 修正或删除以下测试：行为被改坏时仍能通过，或者只改内部实现就失败。
4. **最后才写文档或代理规则，只用来记录需要判断的事项。** 跳过这类文字本身不会让检查失败。

## 修复并证明

立即修掉最常见的类别，每类单独形成一个提交，前提是允许在当前 Git 仓库提交。没有提交授权或仓库未使用 Git 时，仍将各类修正独立呈现。证明每项新检查都能拦住一个真实的历史错误。用 `run_command` 在本地执行与 CI 相同的命令。例外记录在触发规则的那一行，附原因、到期日与人工批准。

## 维护规则表

在代理指令文件里维护一张表，逐条对应规则及其强制机制。操作人纠正你时，修掉错误并补充规则。已有规则但没有约束机制，视为重复错误，在同一次改动中用能奏效的最高层修复。错误从结构上已经无法发生时，移除相应的文字规则。

**回复**逐类列出证据、所选层级，以及更高层级为何不可行。
