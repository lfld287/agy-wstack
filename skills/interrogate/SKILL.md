# Interrogate

让多位审查者独立验证变更或设计的失败路径。只交付有实际运行证据的发现，修复由后续任务处理。

## 定题

优先用用户指定的范围。默认从当前分支与基线分支的合并基点开始，包含工作区未提交的变更。非 Git 项目使用明确的产物和快照。在用户描述、提交与 PR 说明中提取意图，按 `in-your-own-words` 重述。意图无法判定时用 `ask_question` 澄清。

## 并发审查

沿用 [Arena](../arena/SKILL.md) 的席位选择、工作区分隔和并发方式，读取 `interrogate reviewers`，缺失时从 `agy:pro, agy:flash` 起步并加入已确认的外部席。把范围内的未提交变更按原样放入各独立工作副本，并核对基线。使用可用的原生通用代理或已配置的外部 CLI。

每个简报首行要求读取绝对路径的 `worker.md`。向每个实跑取证席提供相同的范围、意图和任务。

> 尝试证明这次变更的行为与意图冲突。在真实代码上运行测试、最小复现或检查命令。审查设计或计划时，可运行原型或探查当前代码。复现文件留在你独占的目录。对每个发现报告标题、实际命令、原始输出以及符合意图时应得到的结果。未运行的猜测、风格、命名、结构建议和依赖未来改动的风险无需报告。可以返回无发现。

同一轮先为各 `codex:` 或 `pi:` 席调用 `run_command`（`WaitMsBeforeAsync: 500`），执行 `scripts/multi-model-dispatch.sh` 的绝对路径，传入该席的模型、工作区、提示词和独立输出。随后在同轮为 `agy:*` 席并发逐席调用 `invoke_subagent`，每次在顶层传 `TypeName`、`Role`、`Prompt`、`Model`、`Workspace`。用 `manage_task` 确认外部任务的终态、退出码和产物。记录可用席、退席及实际模型。

对能用只读工具取证的检查使用只读模式。Pi 的只读模式没有内建执行工具。需要实跑复现的对抗席改用隔离副本上的可执行模式或支持执行的其他引擎，并在简报中禁止修改待审实现和原始工作区。无法安全隔离时，子代理给出命令建议，父会话在授权范围内实际运行后再判定。

## 验证与输出

父会话在相同基线上重跑每个发现的命令，确认输出确实表明失败且违背意图。合并同根因的发现，舍弃未复现项。使用其他引擎的证据时对照同一基线和预期行为。无需评选单个审查者的整份输出。

- **意图**。写明重述后的预期行为和审查范围。
- **已验证发现**。逐项附命令、实际输出、期望、冲突点和发现该问题的审查者。无保留项时写「没有已验证的发现」。
- **舍弃与缺口**。按审查者列出舍弃数和原因，并标记失败或未覆盖的席位。
