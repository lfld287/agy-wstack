# Notes 验证地图

本目录是验证 Notes 用户可见行为的维护依据。操作之前先读索引，再按对应功能文件的步骤验证。

## 基线前置条件

- 在 `http://127.0.0.1:4173` 启动 Notes，使用可丢弃的数据目录。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，这样并行运行不会共享状态。
- 预置标题分别为 `Quarterly plan` 和 `Grocery list` 的笔记。
- 确保 `control-notes` 和 `notes` CLI 都在 `PATH` 上。
- 运行 `control-notes doctor`，要求 URL、数据目录以及构建版本与预期一致。
- 仅操作本轮验证启动的实例。

## 驱动约定

- 除非某条流程的前置条件另有说明，每条都从基线状态开始。
- 优先采用 ARIA 角色及无障碍名称，减少对 CSS 选择器或 DOM 位置的依赖。
- 原样执行各条命令，保持引号内的名称和参数原样。
- 浏览器操作走 `control-notes browser`。
- 终端操作走 `control-notes cli -- <command>`。
- 改写数据后恢复种子数据。清理时保留证明产物。

## 证明与跳过记录

- 同时采集用户操作与结果状态。
- UI 证明包含 ARIA 快照和能看出应用标识的截图。
- CLI 证明包含命令、stdout、stderr 和退出码。
- 数据改写的证明包含通过另一个只读视图读到的保存值。
- 每件产物都记录功能 ID 和实际使用的入口。
- 报告不可达路径时，附上尝试的命令和未满足的前置条件。
- 被跳过的入口保持未验证，其他路径的结果无法替代。

## 功能条目格式

每个功能文件以一级标题和一段用户可见行为说明开头，再按顺序使用以下四个二级标题。

1. `子功能` 列出简短的 ID，每种行为一行。
2. `如何进入（用户视角）` 列出用户的全部入口。
3. `使用 <harness> 驱动` 以「前置条件」开头，实际标题中的 `<harness>` 替换为所用工具。后续条目逐项命名，把用户动作、精确命令和可观测结果放在同一条里。
4. `注意事项` 列出会浪费时间或使验证失效的陷阱。

地图只记录用户路径、稳定标识、必要状态、命令和可观测证据。实现细节留在代码中。

## 功能

- [创建笔记](./create-note.md) 覆盖浏览器和 CLI 创建、取消、持久化以及清理。
- [搜索笔记](./search.md) 覆盖工具栏、键盘与 CLI 搜索，以及有结果、无结果和清除查询的状态。
