# 质疑前提

当两个或更多基于同一前提的修复都没通过同一项验证时，优先怀疑它们的共同前提。

- 用一句话写下每个失败的修复都依赖的前提。
- 在做下一次修复前检验它。找出一项在前提为假时会得到不同结果的观测，并实际观测。既看失败的程度，也看失败的分布。
- 如果证据与前提矛盾，找出失败案例中前提未能预测的共同点。如果某一部分始终落在不利的一侧，就改变导致这一结果的机制，避免再加一层事后补救机制。

写下并检验前提之后，才能开始下一次修复。
