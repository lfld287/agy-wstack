# 解释测量结果

- **运行前先写明要做的决策。** 写明什么结果会改变决策，以及噪声基线是多少。如果多次运行之间的波动幅度大于观察到的效应，就停止。
- **问一句「为什么不能翻倍？」** 用运行期间采集的性能剖析数据或计数器，指出限制结果的具体资源或代码路径。单靠读代码做出的猜测不足以确认瓶颈。
- **列出还可能测到了什么**（错误、被跳过或命中缓存的工作、从未执行的代码、对比中未经调优的一方、噪声，或占比太小、对整体无关紧要的一段工作），并用证据逐项排除。
- **记录数字时，一并保留运行次数、结果的波动范围和限制因素。**

如果测的是性能，按 [benchmark-checklist](../benchmark-checklist/SKILL.md) 技能执行。如果是评测结果，问清每次运行是否都完成了任务、差距是否在多轮试验和不同模型中都成立，以及该场景是否重要。
