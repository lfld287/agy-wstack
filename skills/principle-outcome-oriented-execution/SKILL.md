# 以结果为导向执行

优先确保最终达到预期且可验证的状态。中间阶段的平稳可以让位于这一目标。

为了让每个中间阶段都完全稳定而添加的临时兼容代码，常常会变成长久的技术债。逐步收敛到目标架构，在明确划定的验证节点证明结果正确。

**基本规则**

- 最终状态的完整性优先于过渡阶段的稳定性。
- 计划内、范围明确且可恢复的中间阶段故障可以接受。

**适用约束**

- 用于已有计划且阶段边界明确的重写和迁移。
- 明确指出允许暂时出问题的范围。
- 迁移期间，保留能有效发现当前改动区域问题的检查。
- 计划完成时，必须做完整的静态验证和运行时验证。
