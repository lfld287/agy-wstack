# 为领域建模

用数据结构表达领域规则，避免把规则散布在条件分支里。合适的结构能让无效状态无法表示，并消除分支。

分散的布尔标志或阶段检查可以收进状态机，松散的参数可以收进带类型的模型，散布在多个文件里的分支可以用映射、注册表或可辨识联合类型代替，随手修改状态的逻辑可以收敛到 reducer。访问模式有相应需求时，使用索引、队列或规范化的集合。

无需强行建模。当数据形态清晰、影响范围局部且不太可能扩张时，保留直白的代码。警惕只增加间接层、却没有消除任何分支或无效状态的抽象。

如果新功能给 `if/else` 链又加了一个分支，或引入了必须始终与第一个布尔标志同步的第二个标志，就说明遗漏了领域建模。
